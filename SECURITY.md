# Security policy

SpoolSteward sits in front of a print server and handles logins, print keys and an audit trail, so security reports are welcome and taken seriously.
It is a one-person project: replies are best effort, there is no bounty.

## Reporting a vulnerability

**Do not open a public issue for a security problem.** Use GitHub's private reporting instead:

1. Open the **Security** tab of this repository.
2. Choose **Report a vulnerability**.

Only the maintainer sees the report. Please include the version (`SPOOLSTEWARD_VERSION` in `.env`), what you did, what you
expected and what happened, and, if you can, the smallest steps that reproduce it. Never include real passwords, print keys, the TLS private key or
`SPOOLSTEWARD_SECRET_KEY`.

What to expect: an acknowledgement within about 7 days; a fix or a clear answer as soon as it can be reproduced and understood; credit in the
release notes if you want it. Please give a reasonable time to fix the problem before you publish details.

## Supported versions

Only the newest release receives security fixes. Pre-releases (`-beta.N`) are test versions: report problems there too, but the fix arrives in the
next release, not as a patch of the beta.

## What is in scope

A flaw in SpoolSteward itself that the documentation does not already describe. For example: bypassing authentication or the quota and permission
checks; acting as another user or as an administrator; reading or changing the data of other users; a print key, password, secret key or file name
that the software writes to a log, shows to someone who should not see it or stores in clear; path traversal or injection in the portal, the IPP/eSCL
proxy, the backup and restore code or the update scripts; advice in the documentation that leaves the server less safe than it says.

## What is not

- Anything the documentation already states as a limit or a user's responsibility ([docs/en/limitations.md](docs/en/limitations.md),
  [docs/en/accounts.md](docs/en/accounts.md)): for example a person who gives their print key to somebody else, the scan window comparing only the
  TCP address, or `SPOOLSTEWARD_ESCL_ANONYMOUS=true` accepting scans from anybody on the network (both are off or marked as a last resort for that reason).
- Certificate warnings caused by using the self-signed certificate generated by `scripts/docker-init.sh`.
- Attacks that need root on the server, access to `.env`, `config/` or the Docker socket, or physical access to the machine.
- Problems in CUPS, ipp-usb, Docker, the operating system or the printer firmware themselves (report those to their projects).
- Denial of service by someone who already has a valid account and a quota.

## Hardening notes for administrators

- Keep `SPOOLSTEWARD_SECRET_KEY` private and backed up ([docs/en/data-protection.md](docs/en/data-protection.md)); encrypt the disk and the backups.
- Leave the optional `updater` container off unless you want the Update button: it holds the Docker socket, which is full control of the server.
- Do not expose port 8631 to the internet. The gateway is built for a LAN or a VPN.
